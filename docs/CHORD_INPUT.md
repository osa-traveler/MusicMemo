# コード入力ビュー 要件案

2026-11-18 作成。たたき台。画面の形は Claude Design と相談して決める。
決まったら [SPEC.md](SPEC.md) の未決事項と [APP_SPEC.md](APP_SPEC.md) に反映し、この文書は「決めた理由」の記録として残す。

## 1. 目的

MusicMemo は「コードとメロディを素早くスケッチして Logic へ渡す」アプリ。いまはコード進行を**入れる手段が無い**（サンプル曲のコードは開発用に埋め込んだもの）。
コード入力ビューは、曲の流れを考えながら、手を止めずにコード進行を置いていくための画面。

**大事にしたいこと**

- 理論を知っていれば速く、知らなくても「キーに合うコード」から選べる
- 譜面入力（鍵盤で音符を置く）と同じリズムで、置いたら次の位置へ進む
- 押したら鳴る。耳で確かめながら選べる
- iPad の指操作が主。Mac ではキーボードでも速く入れられる

## 2. いまの状態（実装済みのもの）

| 項目 | 内容 |
| --- | --- |
| データ | `ChordEvent`（開始位置 tick ＋ コード）。コードはルート・質（19種）・分数コードのベース音・♭で綴るか。**次のコードまで持続**する（終わりは持たない） |
| 質（19種） | （メジャー）、m、7、maj7、m7、dim、aug、sus4、sus2、6、m6、9、maj9、m9、add9、m7b5、dim7、7sus4、mMaj7 |
| 文字からの解析 | 「Dm7」「C/E」「Bbmaj7」「F#m7b5」などを読める。表記ゆれ（M7、△7、-7、°、ø、+）も読める |
| 表示 | 役割が「コード」のトラックの五線の上にコードネーム（オレンジ #C2541F、15pt 太字）。全体ビューの小節カードにもコード名 |
| 鍵盤 | 編集位置のコードの構成音にオレンジの点（「Dm7 のコードトーン」） |
| 書き出し | MusicXML にコード記号（メロディのパートに付ける）。MIDI には載らない |
| 移調 | 曲の設定でキーを変えると、コードも一緒に移調できる |
| 無いもの | 入力・変更・削除・移動の操作、N.C.（コードなし）、試聴 |

画面の構成（基準 iPad 11インチ横 1194×834）：上から トップバー 64 ／ セクション行 24 ／ 譜面ビュー（可変）／ 全体ビュー 70 ／ 入力パレット 206。
入力パレットは左から 音価（幅228）／鍵盤（可変）／入力方法（幅168：鍵盤・譜面を直接タップ・MIDIキーボード の切替。後ろの2つは未実装）。

## 3. 使う場面

1. **進行を先に作る**：メロディの前に、8小節の進行を1小節ずつ置いていく（例：C → Am → F → G）。小節の頭に置くことが一番多い
2. **メロディに合わせて付ける**：メロディを入れたあと、その音に合うコードを探して付ける。候補を押して鳴らし比べたい
3. **一部を差し替える**：「ここを IV じゃなくて ii にしたら？」と1つだけ替えて聴き比べる
4. **1小節に2つ**：2拍ずつ（C G）や、3拍＋1拍などで置く
5. **ひねりを入れる**：借用和音（♭VI、♭VII、iv）、セカンダリードミナント（V/V、V/vi）、分数コード（C/E、G/B）を使う
6. **繰り返しを写す**：Aメロの進行を2回目にもそのまま使う（セクションの複製では足りない、部分的なコピー）

## 4. 機能要件

### 4.1 必須（最初の版）

**置く位置**

- 編集位置（赤い線）にコードを置く。位置は**拍単位**（小節の途中は拍の頭だけ）
- 置いたら次の位置へ進む。進む幅は「1小節／2拍／1拍」から選べる（初期値は1小節）
- 同じ位置にすでにコードがあれば置き換える
- 位置はルーラ・全体ビューのカード・譜面のタップで動かせる（今と同じ）。コード入力中は、拍の頭へ吸い付く

**選ぶ**

- **ダイアトニック**：キーに合わせた7つ（長調なら I ii iii IV V vi vii°）。度数（ローマ数字）とコード名を両方出す（例：「IV / F」）
- **質の変更**：選んだコード、または次に置くコードの質を変える（3和音 ↔ 7th、sus4、add9 など）。19種を全部は並べず、よく使うものを先に（下の 4.4 で相談）
- **借用・セカンダリー**：同主調からの借用（♭III ♭VI ♭VII iv）と、セカンダリードミナント（V/ii V/iii V/IV V/V V/vi）をひとまとまりで出す
- **分数コード**：ベース音を選べる（構成音の転回形を先に、その他の音も選べる）
- **ルートから自由に**：12のルート × 質で、どんなコードでも作れる（ダイアトニックに無いもの用）
- **文字で入力**（Mac）：「Dm7」と打って Return。iPad ではあれば良い

**聴く**

- コードを押したら鳴る（置く前の試聴と、置いたときの両方）。音色は役割が「コード」のトラックの音色（無ければ選択中のトラック）
- 置いたコードの位置から1〜2小節を再生して確かめる操作があると良い（スペースキーの再生で足りるかも）

**直す**

- 置いたコードを選ぶ → 置き換え・質の変更・削除
- 削除したら、前のコードがそのまま続く（持続の扱いはいまのまま）
- 元に戻す／やり直すで戻せる
- **N.C.（コードなし）** を置ける（いまは表せない。データに「コードなし」を足す）

### 4.2 あれば良い（次の版以降でも良い）

- コードを拍単位でドラッグして動かす
- 範囲（例：4小節）の進行をコピーして別の位置へ貼る
- 「よく使う進行」の候補（I–V–vi–IV、ii–V–I、王道進行 IV–V–iii–vi など）を一度に置く
- メロディの音から候補を絞る・並べ替える（その小節のメロディの音を多く含むコードを上に）
- 直前のコードからの「次に来やすいコード」をハイライト（V → I、ii → V など）
- ボイシング：コードを置いたら、コードトラックに音符（例：全音符の和音）も自動で入れる（4.4 で相談）
- Apple Pencil で書いたコードネームを読み取る（SPEC の B案）
- 度数パッド・移動ドでの入力（SPEC の C案）

### 4.3 今回入れないもの

- テンションの細かい指定（♭9、#11、13 などを自由に組み合わせる）。質の19種で足りない分は後で
- 転調（曲の途中でキーが変わる）。キーは曲に1つのまま
- コード進行の自動生成

### 4.4 決める必要があること

| # | 論点 | 選択肢 | おすすめ |
| --- | --- | --- | --- |
| 1 | 画面の形 | A ダイアログ（シート）／B サイドバー（右）／C 入力パレットの切り替え（下の 5章） | C |
| 2 | 入力のモード | コード入力中は鍵盤を隠すか、鍵盤と並べるか | 隠す（パレットを切り替え）。鍵盤の構成音表示は音符入力に戻ったときに見える |
| 3 | 質の並べ方 | 19種を全部並べる／よく使う8種＋「その他」 | よく使う8種（なし・m・7・maj7・m7・sus4・add9・dim）＋その他 |
| 4 | 進む幅 | 固定（1小節）／選べる（1小節・2拍・1拍） | 選べる。初期値は1小節 |
| 5 | ボイシングの自動入力 | しない／する（コードトラックに和音を入れる）／選べる | 最初はしない。コードネームと音符は別に持つ（Logic 側で作り直すことが多いため）。後で「コードトラックに和音を入れる」を足す |
| 6 | 試聴の音色 | コードトラックの音色／ピアノ固定／選択中のトラック | コードトラックの音色 |
| 7 | ダイアトニックの短調 | 自然的短音階だけ／和声的短音階の V（E7 in Am）も並べる | 自然的短音階＋V7 を並べる（短調で一番よく使うため） |
| 8 | 置いたコードの見え方 | いまの「コードトラックの五線の上」だけ／ルーラの下に専用のコード行を足す | 専用のコード行（全トラック共通、どのトラックを選んでいても見えて選べる）。高さ 22 前後 |

## 5. 画面の形の候補

### A：ダイアログ（シート）

全体ビューのカードや譜面をタップ → 「コードを選ぶ」シートを開く → 選んで閉じる。

- 良い：画面の他の部分を変えずに済む。一度に多くの候補を大きく出せる
- 悪い：1つ置くたびに開いて閉じる。「進行を続けて置く」場面（3章の1）に向かない。譜面が隠れて前後の流れが見えない

### B：サイドバー（右、幅 300 前後）

右端にコードパネルを出す（開閉できる）。

- 良い：譜面と全体ビューを見ながら続けて置ける。候補を多く並べられる
- 悪い：譜面の幅が 300 狭くなる（100%で4小節 → 3小節弱）。iPad の縦向きでは苦しい。鍵盤との行き来が遠い

### C：入力パレットの切り替え（おすすめ）

入力パレット（高さ206）の右端「入力方法」に **「コード」** を足し、選ぶと鍵盤の場所がコードパネルに替わる。音価の場所は「進む幅」と「質の変更」に使う。

```
┌ 進む幅 ──────┐┌ ダイアトニック（C major）───────────────┐┌ 入力方法 ┐
│ [1小節][2拍][1拍] ││ [ I  ][ ii ][ iii][ IV ][ V  ][ vi ][vii°] ││ 鍵盤     │
│ 質              ││ [ C  ][ Dm ][ Em ][ F  ][ G  ][ Am ][Bdim] ││ 譜面     │
│ [ - ][ m ][ 7 ][maj7]││ 借用・セカンダリー                          ││ MIDI     │
│ [m7][sus4][add9][…]││ [♭III][♭VI][♭VII][ iv ][V/V][V/vi][ … ] ││ ▶コード  │
│ [N.C.] [/ベース]   ││                             [⌫ 消す] [ルート…] ││          │
└──────────────┘└──────────────────────────┘└─────┘
```

- 良い：画面の構成を変えない（譜面の広さはそのまま）。「入力方法」の切り替えというすでにある考え方に乗る。音符入力とコード入力を行き来しやすい
- 悪い：高さ 206 に収める必要があり、候補を一度に出せる数が限られる（ルートから自由に作る操作は1段奥になる）

## 6. 見た目の決まり（いまのデザインとそろえる）

- 色：コード関係はオレンジ #C2541F（コード名、構成音の点）。操作の選択状態はコバルトブルー #2F5BEA。編集位置は赤 #D92D20。紙面は白、背景は #EEF0F2
- ボタン：角丸 10、枠 #C9CDD3、高さ 34〜44（指で押せる大きさ。最小 44 を目安）
- 文字：コード名は太字。度数（ローマ数字）は小さめのグレー（#5A606B）で添える
- 基準画面：`docs/screens/01_main_100.png`、寸法は `docs/reference/01_main_100.html`

## 7. 進め方の案

1. **データ**：N.C. を表せるようにする。コードの追加・置き換え・削除・移動（モデルとテスト）
2. **画面の形を決める**：この文書をもとに Claude Design と相談し、モックを作る
3. **最小の入力**：パレットの「コード」で、ダイアトニック＋質の変更＋試聴＋進む＋消す
4. **広げる**：借用・セカンダリー、分数コード、ルートから自由に、Mac の文字入力、コード行
5. **あれば良いもの**：ドラッグでの移動、コピー、進行の候補、メロディからの絞り込み、ボイシング

## 8. Claude Design に相談したいこと

- 5章の A／B／C のどれが良いか。C の場合、高さ 206 の中でダイアトニック・借用・質・N.C.・ベース音をどう並べるか
- 度数とコード名の両方を、ボタンの中にどう見せるか（どちらを主にするか）
- 置いたコードの見え方（4.4 の 8：専用のコード行を足すか）と、選んだコードの見え方
- 「次に来やすいコード」のハイライトを入れる場合の見せ方（目立ちすぎない程度に）
- iPad の縦向き（834×1194）でも破綻しないか
