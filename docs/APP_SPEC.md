# MusicMemo アプリ仕様（実装済みの内容）

2026-10-13 時点。デザイン段階の仕様は [SPEC.md](SPEC.md)、まだ無い機能と既知の制限は [ROADMAP.md](ROADMAP.md) にある。
ここには「いまのアプリがどう動くか」と、実装しながら決めた値を書く。

## 技術構成

| 項目 | 内容 |
| --- | --- |
| 対象 | iPadOS 26 / macOS 26 以降。SwiftUI のマルチプラットフォーム（Mac Catalyst は使わない） |
| プロジェクト | XcodeGen（`project.yml`）で生成。1つのアプリターゲットで iPad と Mac に対応 |
| モデル層 | ローカルの Swift Package `MusicMemoCore`。曲データ・記譜・入力・書き出しを UI から切り離し、`swift test` で検証 |
| 譜面の記号 | Bravura（SMuFL）のグリフを輪郭（パス）として描く。五線・符幹・連桁などは線で描く |
| 音 | AVAudioUnitSampler ＋ FluidR3_GM（SoundFont、MIT。リポジトリには含めず取得スクリプトで入れる）。再生は自前のスケジューラ |
| 保存 | 1曲＝1ファイル（`.musicmemo`、中身は JSON）。SwiftUI の DocumentGroup で開く・自動保存 |

## 画面構成

基準は iPad 11インチ横向き（1194×834pt）。上から5段で、譜面ビューだけが高さ可変。

| 領域 | 高さ | 内容 |
| --- | --- | --- |
| トップバー | 64 | 戻る、曲名と曲の情報、再生／ループ／メトロノーム、元に戻す／やり直す、Logicへ書き出し |
| セクション行 | 24 | セクションのチップ、右端に表示範囲・トラック数・入力位置 |
| 譜面ビュー | 可変 | 再生範囲バー18＋ルーラ28＋トラック行。左にトラック情報列（幅196、倍率に依らず固定）、右に縦スクロール列（幅16） |
| 全体ビュー | 70 | セクション名＋小節カード。左右は譜面部分にそろえる |
| 入力パレット | 206 | 音価（幅228）／音高（鍵盤）／入力方法（幅168） |

動くボタン：戻る、再生／停止、ループ、メトロノーム、元に戻す／やり直す、書き出し、セクションのチップ、トラックの M／S。
まだ動かないボタン：＋セクション、音色…、入力方法の「譜面を直接タップ」「MIDIキーボード」。

## 譜面ビュー

### 横方向の座標（倍率100%）

- 1小節 222pt。小節線から 28pt 右が1拍目で、4分音符1つ（480 tick）が 48pt（0.1pt/tick）
- 音符・ルーラの目盛り・編集位置は同じ計算式で置くので、必ず揃う
- 再生範囲の端と青い点線は、小節頭なら小節線の位置、それ以外は音符の位置に置く
- 左端 56pt（調号があればその分広い）は音部記号と調号の固定領域。横スクロールしても動かず、小節はその下を流れる
- 拍子記号は曲頭（1小節目の前）だけに描く。固定領域の先頭トラックには、左端に見えている小節の番号を出す

### トラック行

- 五線の間隔 8pt。行の高さは「五線に必要な高さ（90pt×倍率）」と「トラック情報が収まる高さ」の大きい方
- トラックが少ないときは行を伸ばして譜面ビューを埋めるが、伸ばすのは五線の高さの 1.1 倍まで（縮小時に行間が空きすぎないように）
- コードトラック（役割が「コード」）は五線の上にコードネーム（オレンジ、15pt 太字）
- 選択中のトラックは、トラック情報を薄い青にし、編集位置の小節を薄い青で塗り、入力予定の音を半透明の青で出す
- 五線をタップすると、そのトラックを選び、編集位置もタップした位置へ動かす（16分単位）

### トラック情報（倍率で4段階）

| 倍率 | 表示 | 行の高さの下限 |
| --- | --- | --- |
| 150%以上 | 楽器名＋役割、Vol、Pan、M／S／音色… | 140 |
| 75%以上 | 楽器名＋役割、Vol、Pan（C／L16／R20 形式） | 90 |
| 55%以上 | 楽器名＋役割、Vol とパン値の1行 | 58 |
| 55%未満 | 楽器名＋役割だけ | 34 |

### ルーラと編集位置

- 目盛りは 小節（番号付き）＞拍＞8分＞16分。150%以上で拍番号、75%未満では8分・16分を間引く
- 左列に「小節 · 拍」と現在位置（7 . 1 . 1）を赤字で表示
- 赤い編集位置ライン（2pt）と三角マーカー。音部記号の領域に入ったら隠す
- ルーラをタップ／ドラッグすると編集位置が 16分単位で動く

### 再生範囲バー

- 青い帯と両端のつまみ。つまみをドラッグして範囲を変える（拍単位で吸い付く、つまみから 22pt 以内で掴める、始点と終点は1拍以上あける）
- 帯に「ループ 6–7小節」（ループがオフなら「6–7小節」、端が拍の途中なら「6.3–8.1」）
- 範囲の端から全トラックを貫く青い点線。左列に「再生範囲 6.1 → 8.1」
- どの倍率でも表示する。トップバーのループボタンで、ループのオン／オフを切り替える

### 縦スクロール

- 右端の縦スクロールバー（幅8）。つまみの長さ＝表示中の高さ／全体の高さ。つまみのドラッグでもスクロールできる

### 起動時の位置

- 編集位置の小節が、見える小節数の6割ほどの位置に来るように横スクロールする（100%では 5〜8小節を表示）

## 記譜のルール

- 音名の綴り：調の音階音は調号どおり。音階外の音は、幹音で書けるならそのまま、書けなければ主音からの度数で決める
  - 長調：♭II・♭III・♭VI・♭VII は♭、♯IV は♯（C major なら D♭・E♭・F♯・A♭・B♭）
  - 短調：♭II は♭、それ以外（♯IV・♯VI・導音・長3度）は♯（A minor なら G♯）
- 臨時記号は小節線まで持続（同じ小節の同じ高さには繰り返さない）。調号と同じなら付けない
- 調号は音部記号の横に描く（C major 以外）
- 符幹は真ん中の線から一番遠い音で向きを決める（真ん中の線上や同じ距離なら下向き）。長2度でぶつかる符頭は反対側へずらす
- 連桁：同じ拍の中で続く8分・16分（休符で区切る）を水平の連桁でつなぐ。16分どうしは2本目、孤立した16分は短い2本目
- 3連符：続く3連符を元の音価2つ分ずつまとめ、「3」を付ける
- タイ：弧を符幹と反対側に描く（和音の一番上の音は上側）
- 1つの記号で書けない長さは、近い記号で代用して描く（入力時は分割してタイでつなぐので、通常は起きない）

## 全体ビュー

- 1小節＝1枚のカード（高さ46）。コード名＋小さな五線。小さな五線には選択中のトラックの音を点で出す
- 入力中の小節は薄い青＋青い点。空の小節（その小節で始まるコードが無く、どのトラックにも音符が無い）は点線とグレー、「—」
- コードが2つある小節は「C G」のように並べる
- セクション名はカード列の上に左罫線付きで出す。編集位置のあるセクションは墨色の罫線。頭が左に隠れているときは左端に貼り付く
- 青い枠＝譜面に見えている範囲（スクロールになめらかに追従）
  - 枠の中からドラッグ：譜面を横スクロール
  - 枠の両端のつまみ（12pt 以内）をドラッグ：その小節数がちょうど見える倍率にズーム（反対側の端は動かさない）
  - カードをタップ：その小節の頭へ編集位置を移す（見えていなければスクロール）
- 長い曲：カードは最小 40pt まで縮め、それでも収まらなければ全体ビュー自体が横にずれて枠に追従する（端から 12pt 以内に入らないように）

## セクション行

- チップ：編集位置のあるセクションを黒で表示。タップするとそのセクションの頭へ編集位置を移し、左端に来るようにスクロール
- 右端：「表示 5〜8小節 · 入力位置 7小節 1拍目」。全トラックが見えていないときかズーム中は「· 2/6トラック」を加える

## ズーム

- 操作：iPad はピンチ。Mac はトラックパッドのピンチ、⌘＋ホイール（マウスの位置が基準）、表示メニュー（⌘＋／⌘−／⌘0）
- 指（マウス）の下にある小節とトラックが、拡大・縮小しても同じ場所に残るよう、縦横のスクロールを補正する
- 範囲 40%〜250%。HUD の −／＋ とメニューは 40・50・75・100・150・200・250% の段階で動く
- 倍率HUD：ズーム中とその後 1.8 秒、譜面ビュー上部中央に「− 倍率 ＋ ｜ 100%に戻す」
- 文字（コードネーム・小節番号）は倍率どおりに縮めず、80〜90% を下限にする
- 150%以上：拍番号、譜面に8分ごとの薄い縦線、トラック情報に M／S／音色

## 入力

### 入力パレット

- 音価（3×3）：全音符・2分・4分・8分・16分・付点／4分休符・タイ・3連符。絵は Bravura＋線で描く。選択中は青地に白
- 付点・3連符はもう一度押すまでオンのまま。タイは1回使うとオフに戻る
- 休符ボタン：選択中の音価の休符をすぐ入力して進む（8分を選んでいれば8分休符）
- 鍵盤：2オクターブ（白鍵14・黒鍵10）。C の白鍵に音名。編集位置のコードの構成音にオレンジの点（見出しに「Dm7 のコードトーン」）
  - 初期範囲はトラックの音部記号に合わせる（ト音記号 C4–B5、ヘ音記号 C2–B3）。‹ › で1オクターブずつ（C1〜C7 の範囲）、トラックごとに覚える
  - 押している鍵は青く強調。押していないときは直前に入れた音を強調
- 「戻って消す」：鍵盤の見出しの行にある（入力方法ブロックに置く高さが無いため）
- 入力方法：「鍵盤」のみ。「譜面を直接タップ」「MIDIキーボード」は詳細が未決なので選べない

### 入力の流れ（上書き方式）

1. 選択中のトラックの編集位置に、選択中の音価で音符を置く
2. 重なる既存の音符は消すか手前で切り詰める（後ろの音符はずらさない）
3. 小節線をまたぐ長さ、1つの記号で書けない長さ（4分＋16分など）は分割してタイでつなぐ（休符はタイなし）
4. 鍵を全部離したら、編集位置を入力した音の終わりへ進める
5. 編集位置が画面の外へ出そうになったら、左から 1/3 あたりに来るよう横スクロールする

- 和音：iPad は同時に押す（全部離したら進む）。Mac は ⇧を押しながらクリックで、直前の音に重ねる（進まない）
- 戻って消す（ボタン／Mac の Delete）：編集位置の直前の音符（和音ならまとめて）を消して、その位置へ戻る。消した音へのタイは外す
- 元に戻す／やり直す（ボタン／⌘Z・⇧⌘Z）：音符の編集が対象。曲データと編集位置を一緒に戻す（音量・パン・再生範囲・ループ・倍率は対象外）

## 再生

- 再生／停止：トップバーの再生ボタン（再生中は停止ボタンになる）、またはスペースキー
- 始める位置：ループがオンなら再生範囲の始点から（編集位置が範囲の中にあれば編集位置から）。オフなら編集位置から曲の終わりまで
- 再生中は赤い線とルーラの三角・「小節 · 拍」が再生位置を示す。画面の右端に近づくとページ送りのようにスクロールして追う（ループで戻ったときも追う）
- 止めると、赤い線は再生を始めた位置（編集位置）に戻る
- ループ：再生範囲の終わりで鳴っている音を止め、始点へ戻って続ける
- ミュート・ソロ：トラックの M／S を反映（ソロがあるときはソロのトラックだけ）。再生中に切り替えてもすぐ反映
- 音量・パン：トラックの Vol／Pan を反映
- メトロノーム：トップバーのボタンでオン／オフ（再生中も切り替えられる）。GM ドラムのウッドブロックで、1拍目は高い音で強め。カウントインは無い
- 再生中に鍵盤を押すと音だけ鳴り、入力はしない
- 再生中に曲を編集したら（元に戻すなど）、同じ位置から続けて新しい内容を鳴らす
- 仕組み：専用の高優先度スレッドが2ミリ秒ごとに起き、時刻どおりにサンプラーへ発音・消音を送る（`App/Audio/PlaybackScheduler.swift`）。AVAudioSequencer は落ちることがあったため使っていない
- 音符の強さは一定（ベロシティ 90）。タイでつながった音は1つの長い音にまとめる

## 音

- トラックごとに AVAudioUnitSampler を1つ持ち、トラックの GM 音色（プログラム番号）を読み込む。音量・パンはトラックの Vol／Pan を反映
- 音源：同梱の FluidR3_GM（iPad と Mac で共通）。無いときは、Mac だけ macOS 標準の音源（gs_instruments.dls）で鳴らす
- GeneralUser GS は AVAudioUnitSampler で再生すると落ちることがあったため使わない（v2.0.0〜v2.0.3 で再現。FluidR3_GM と macOS 標準の音源では再現しない）
- 鍵盤を押すと選択中のトラックの音色で鳴り、離すと止まる（ミュート・ソロは鍵盤の音には効かない）
- 新しいトラックの初期音色はピアノ（GM 0）
- 音色は起動時に専用のキューで読み込む（エンジンが動いている間に読み込むと落ちることがあるため）。音源が無いときは鳴らさずログを出す
- iPad ではオーディオセッションを playback にする（消音スイッチがオンでも鳴る想定）

## 保存（1曲＝1ファイル）

- 1曲を1つのファイル（`.musicmemo`、形式 ID `local.osa.musicmemo.sketch`）に保存する。中身は JSON で、形式の版（`formatVersion`）・曲データ・画面状態（編集位置、選択中のトラック、倍率、選択中の音価とタイ）を持つ。より新しい版のファイルは開かない
- iPad：起動するとシステムのファイル一覧（新規作成・開く・名前の変更・複製・削除）。iCloud Drive に置けば Mac と共有できる
- Mac：ファイルメニュー（新規・開く・最近使ったもの）。1曲ごとにウィンドウが開く
- 変更は自動で保存される。開き直すと、編集位置などの画面状態も戻る（元に戻す／やり直すの履歴は保存しない）
- 曲名はファイル名と同じ（名前の変更は iPad はファイル一覧、Mac はタイトルバー）。書き出すファイルの名前にもなる
- トップバーの「戻る」：再生を止めてファイルを閉じる（iPad はファイル一覧へ、Mac はウィンドウを閉じる）
- 新しい曲のひな形：C major・4/4・♩=120・16小節、セクション「Aメロ」（16小節）、Piano（メロディ）・E.Piano（コード）・Finger Bass（ベース）、コード進行は空
- サンプル曲「スケッチ 03」は、デバッグビルドの開発用（Mac）にだけ残している

## 書き出し

トップバーの「Logicへ書き出し」→「MusicXML（コード付き）／MIDI／MusicXML と MIDI の両方」。ファイル名は曲名。

- Mac：1形式なら保存ダイアログ、両方ならフォルダを選んで書き出す（同名のファイルは上書きせず番号を付ける）
- iPad：共有シート（AirDrop で Mac へ、ファイルに保存、など）
- ミュート中のトラックも書き出す

| 形式 | 内容 |
| --- | --- |
| MusicXML（score-partwise 4.0、`.musicxml`） | 楽器ごとに1パート（音部記号・調号・拍子・音色・音量・パン）。音符・和音・休符・タイ・付点・3連符・臨時記号。コード記号はメロディのパートに付ける（リードシートの形）。セクション名は練習番号、テンポは先頭パート。音符の無い所は休符で埋め、小節の長さを拍子とそろえる |
| MIDI（SMF フォーマット1、480 tick/4分音符、`.mid`） | 1本目にテンポ・拍子・調号・セクション名のマーカー。楽器ごとのトラックにトラック名・音色・音量・パン・音符。タイでつながった音は1つにまとめる。チャンネルはトラック順（10ch は飛ばす） |

MusicXML は 4.0 の公式スキーマで検証済み。MIDI は macOS 標準の MusicSequence で読めることを確認済み。

## データモデル（MusicMemoCore）

| 型 | 主な項目 |
| --- | --- |
| `Sketch`（曲） | タイトル、キー、拍子、テンポ、小節数、セクション、コード進行、トラック、再生範囲、ループ |
| `SongSection` | 名前、開始小節、小節数 |
| `ChordEvent` / `Chord` | 開始位置とコード（ルート、質19種、分数コードのベース音）。次のコードまで持続する |
| `Track` | 楽器名、役割、音部記号、色、音量 0–100、パン −64〜+63、ミュート、ソロ、GM 音色、音符 |
| `Note` | 開始位置、長さ、音高（nil なら休符）、次の音へのタイ |
| `EditorState`（画面状態） | 編集位置、選択中のトラック、倍率、選択中の音価、タイ、入力予定の音高 |

- 時間は tick（4分音符 = 480）。3連符も整数で表せる。位置の表示は「小節.拍.16分」（すべて1始まり）
- スクロール位置や鍵盤の範囲などの画面だけの状態は、アプリ側の `SketchStore` が持つ

## 開発用の仕組み（デバッグビルドのみ）

Mac で、次の環境変数を付けて起動すると働く。撮影・確認用の環境変数があると、保存なしでサンプル曲「スケッチ 03」のウィンドウを開く。

| 環境変数 | 働き |
| --- | --- |
| `MUSICMEMO_SAMPLE=1` | サンプル曲を直接開く |
| `MUSICMEMO_OPEN_FILE=パス` | 起動時にそのファイルを開く（保存と読み込みの確認用） |
| `MUSICMEMO_SNAPSHOT=パス` | 基準サイズ（1194×834）の画面を PNG に保存して終了する |
| `MUSICMEMO_SAVE_ON_EXIT=1` | 撮影して終了する前に、開いているファイルを保存する |
| `MUSICMEMO_ZOOM=倍率` | 起動時の倍率（例：`2`、`0.5`） |
| `MUSICMEMO_INPUT_DEMO=1` | 決まった入力操作（単音・和音・休符・タイ・3連符・戻って消す）を自動で流す |
| `MUSICMEMO_PLAY_CHECK=1` / `2` | メトロノーム付きで再生し、0.5秒ごとの再生位置をログに出す（`1` は各トラックの出力レベルも測る） |
| `MUSICMEMO_SILENT=1` | 音を出さない（再生の自動確認用） |
| `MUSICMEMO_SOUNDBANK=パス` | 音源ファイルを差し替える（音源ごとの不具合の切り分け用） |
