# 音楽のメモ帳 — プロジェクト構想

**プロジェクト名（仮）：音楽のメモ帳 / Music Notepad**

**ステータス：構想・初期設計段階**

## 1. コンセプト

### 音楽のメモ帳

思いついたメロディ、コード進行、音楽的なアイデアを、いつでも気軽に書き留められる作曲支援アプリケーション。

目指すのは、DAW（Digital Audio Workstation）の簡易版ではない。

**音楽を完成させるためのツールではなく、音楽のアイデアを記録し、試し、発展させるためのツール**である。

文章を書くときのメモ帳やスケッチブックのように、音楽を気軽に扱えることを重視する。

### 基本思想

- **素早く記録する**：思いついたコード進行やメロディを、すぐに入力できる。
- **すぐに聴ける**：簡単な伴奏を付けて、その場で試聴できる。
- **未完成を許容する**：数小節だけのアイデアや、コードだけの断片でも保存できる。
- **自由に試行錯誤できる**：コードの置き換え、フレーズの複製、移調、展開を簡単に行える。
- **制作環境につなげる**：Logic ProやSunoなど、既存の制作ツールにアイデアを引き継げる。
- **AIと共存する**：ユーザーが行える編集操作は、原則としてAIからも実行できるようにする。

### 重視すること

機能の豊富さよりも、操作の軽快さを優先する。

音楽理論を意識しなくても使えることを基本とし、必要なときには理論的な情報や高度な編集機能を利用できるようにする。

## 2. 対応プラットフォーム

Apple製品を中心としたマルチプラットフォームアプリケーションとする。

| プラットフォーム | 役割 | 主な用途 |
|---|---|---|
| iPad | メイン | 作曲、コード進行編集、五線譜入力 |
| iPhone | クイックメモ | コード進行の記録、組み替え、試聴 |
| Mac | 編集・連携 | 作曲、編集、Logic Proへの受け渡し |

### iPad

主たる作曲環境。

コード進行とメロディを同時に扱い、楽曲のアイデアを組み立てる。

タッチ操作を基本とし、将来的にはApple Pencilの活用も検討する。

### iPhone

外出先で思いついた音楽を記録するための環境。

特にコード進行の入力と組み替えを重視する。

五線譜の本格的な編集は必須としない。

短時間で起動し、入力・試聴・保存できることを優先する。

### Mac

iPadと同じ楽曲データを編集できる環境。

キーボードやマウスによる操作に対応する。

Logic ProへのMIDI書き出しなど、既存の制作環境との連携を重視する。

### データ同期

iCloudによるデバイス間同期を想定する。

外出先でiPhoneに記録したコード進行を、帰宅後にiPadやMacで編集できることを目指す。

オフラインでも利用可能とし、オンライン復帰時に同期する。

## 3. 作曲ワークフロー

### 基本はコード進行から作曲する

本アプリでは、コード進行を作曲の出発点とする。

例：

```text
C | Am | F | G
```

コード進行を入力し、簡単な伴奏を鳴らしながらメロディを考える。

メロディは五線譜に入力する。

### コード入力

コード名による入力を基本とする。

```text
C
Am
Dm7
G7
Fmaj7
```

ローマ数字によるディグリー表記を主たる入力方法とはしない。

ただし、内部的には調性やコードの機能を扱えるようにすることを検討する。

### メロディ入力

メロディは五線譜で入力・表示する。

初期段階では、タップによる音符入力を想定する。

将来的にはApple Pencilによる入力も検討する。

内部データは五線譜の描画情報ではなく、音高・開始位置・音価などの音楽情報として保持する。

### 楽曲構造

コード進行とメロディを共通の音楽時間軸で管理する。

コードは小節途中でも変更でき、メロディは小節線をまたぐことができる。

また、完成した曲だけでなく、次のような断片も扱えるようにする。

- コード進行だけの8小節
- メロディだけの4小節
- サビの後半だけのアイデア
- 同じフレーズの複数のバリエーション
- テキストによる作曲メモ

## 4. 伴奏・再生機能

### 基本方針

入力したコード進行を、その場で簡単に再生できるようにする。

伴奏はメロディを考えるための補助機能と位置づける。

高度なアレンジ機能や音色編集機能は初期段階では必要としない。

### 伴奏パターン

最初は数種類のシンプルな伴奏パターンを用意する。

候補：

| パターン | 内容 |
|---|---|
| Block Chord | コードを同時に鳴らす |
| Arpeggio | コード構成音を順番に鳴らす |
| Rhythm Chord | 一定のリズムでコードを刻む |
| Bass + Chord | ベース音とコードを交互に鳴らす |

伴奏パターンはコード進行と独立して管理する。

コードを変更しても伴奏パターンは維持される。

将来的には、転回形やボイスリーディングの自動調整も検討する。

### 音源

初期段階では、Apple標準の音声APIを利用する。

想定技術：

- AVAudioEngine
- AVAudioUnitSampler
- SoundFont（SF2）などのサウンドバンク

最初はピアノ音色だけでもよい。

音源の品質や音色のバリエーションは、初期段階では重要視しない。

### 将来の音源拡張

音源処理は抽象化し、将来的に次の方式を追加できる構造とする。

- AUv3音源
- Core MIDIによる外部MIDI出力
- MacのAudio Unit音源

Roland CloudのXV-5080についても検討したが、Mac用プラグインであり、iPadでは直接使用できない。

当面は標準音源で開発を進める。

## 5. 音楽的な編集機能

本アプリの特徴となる領域。

一般的なDAWのように音符を個別に編集するだけでなく、**音楽的な意味を持つ単位で編集できること**を目指す。

### コード進行の編集

コードの追加、削除、変更、複製、並べ替えを行う。

例：

```text
Before:
C | Am | F | G

After:
C | Am7 | Dm7 | G7
```

複数のコード進行を試し、比較できるようにする。

### フレーズの編集

メロディやコード進行を、フレーズ単位で扱う。

将来的に想定する操作：

- フレーズの複製
- 繰り返し
- 移調
- 反行
- 逆行
- リズムの変更
- モチーフの展開

### コードとメロディの関係

将来的には、コードとメロディの関係を解析・編集できるようにする。

例えば、コードをAm7からA7に変更した際、メロディのCをC♯に変更するか、元の音を維持するかを選択できる。

コードトーン、テンション、経過音などの情報を表示することも検討する。

ただし、これらは初期バージョンの必須機能ではない。

## 6. データモデル

### 基本方針

**音楽データと表示方法を分離する。**

五線譜やコード表示は、内部の楽曲データを視覚化するためのUIとする。

楽曲データはMIDIファイルそのものではなく、独自の構造化データとして管理する。

### 主なデータ要素

```text
Project
 ├── Sketch
 │    ├── Metadata
 │    │    ├── Title
 │    │    ├── Tempo
 │    │    ├── TimeSignature
 │    │    └── Key
 │    │
 │    ├── ChordEvents
 │    │    ├── Position
 │    │    ├── Duration
 │    │    └── Chord
 │    │
 │    ├── Melody
 │    │    └── Notes
 │    │         ├── Pitch
 │    │         ├── Position
 │    │         ├── Duration
 │    │         └── Velocity
 │    │
 │    ├── AccompanimentPattern
 │    └── TextMemo
 │
 └── Other Sketches
```

これは概念的な構造であり、実装時に調整する。

### 時間の表現

音楽時間は、秒単位ではなく拍やTickなどの音楽的な単位で管理する。

これにより、テンポ変更時にも音符やコードの位置関係を維持できる。

### 保存形式

JSONなどの構造化形式を候補とする。

楽曲の情報だけでなく、将来的にはフレーズの派生関係や編集操作なども保持できるようにする。

## 7. Logic Pro・Sunoとの連携

本アプリは楽曲制作の前工程を担当する。

最終的な編曲、音作り、ミックスなどは既存の制作ツールに任せる。

### Logic Pro

Standard MIDI File（SMF）で書き出す。

メロディと伴奏は別トラックとして出力する。

MacのLogic Proに読み込み、音源の割り当てやアレンジを行う。

### Suno

WAVなどのオーディオファイルで書き出す。

メロディと簡易伴奏を含むデモ音源をSunoに渡し、アレンジやカバー生成の素材として使用する。

Sunoによる生成結果は、元のメロディやコード進行を完全に保持するとは限らない。

### 出力形式

| 形式 | 用途 |
|---|---|
| 独自形式 | 編集可能なスケッチの保存 |
| MIDI | Logic Proなどへの受け渡し |
| WAV | Sunoなどへの受け渡し |

## 8. AIとの連携

### 基本思想

**ユーザーが実行できる編集操作は、AIからも実行できるようにする。**

AIを特別な編集システムとして実装するのではなく、人間の操作とAIの操作が共通のコマンドAPIを利用する構造とする。

### アーキテクチャ

```text
          User Interface
          (SwiftUI)
              │
              ▼
        Editing Commands
              ▲
              │
         AI Interface
      (Natural Language)
              │
              ▼
        Command Executor
              │
              ▼
          Music Model
              │
       ┌──────┼──────┐
       ▼      ▼      ▼
    Playback  Save   Export
```

UIとAIは同じ編集機能を呼び出す。

AIが直接楽曲データを書き換えることは原則として避ける。

### AIへの指示例

自然言語による操作を想定する。

```text
「最初の4小節を2回繰り返して」

「最後のコードをAmに変更して」

「このフレーズを半音上げて」

「2小節目と3小節目を入れ替えて」

「サビのコード進行を少し切ない感じにして」
```

### コマンドAPI

編集操作を構造化されたコマンドとして定義する。

例：

```json
{
  "command": "repeatBars",
  "source": {
    "startBar": 1,
    "endBar": 4
  },
  "repeatCount": 2,
  "insertAtBar": 5
}
```

この例では、最初の4小節を5小節目以降に2回追加する。

### コマンドの種類

初期段階で想定するもの：

```text
insertBars
deleteBars
copyBars
repeatBars
moveBars

insertChord
changeChord
deleteChord

insertNote
changeNote
deleteNote

transpose
```

将来的には、複数コマンドをまとめた操作にも対応する。

### 読み取りAPI

AIが現在の楽曲を理解できるように、読み取り機能も提供する。

例：

```text
getProject
getSketch
getSongStructure
getChords
getNotes
getSelection
```

AIは現在の楽曲情報や選択範囲を参照し、適切な編集コマンドを生成する。

### Undo / Redo

すべての編集操作は、可能な限り取り消し可能とする。

AIが複数の変更を行う場合は、それらをひとつのトランザクションとして扱えるようにする。

また、AIによる大きな変更は適用前にプレビューできることが望ましい。

### 将来の拡張

コマンドAPIを独立させておくことで、将来的に次のような利用も検討できる。

- クラウドLLMによる操作
- ローカルLLMによる操作
- 外部AIエージェントとの連携
- 自然言語による作曲支援
- 自動編集・自動テスト

AI連携そのものは後から実装するが、**AIから操作可能な構造は開発初期から採用する。**

## 9. 技術構成

現時点での推奨構成。

| 領域 | 技術 |
|---|---|
| 開発言語 | Swift |
| UI | SwiftUI |
| 五線譜描画 | SwiftUI Canvas / Core Graphics |
| 音声再生 | AVAudioEngine |
| 内蔵音源 | AVAudioUnitSampler |
| MIDI | Core MIDI |
| 保存 | Codable + JSONなど |
| データ同期 | CloudKit |
| 対応OS | iPadOS / iOS / macOS |
| AI連携 | 共通コマンドAPI |

### 設計上の重要事項

**1. UIと楽曲モデルを分離する**

iPad、iPhone、Macで異なるUIを提供しても、同じ楽曲モデルを使用する。

**2. 音源を抽象化する**

標準音源、AUv3音源、外部MIDI音源などを将来的に切り替えられるようにする。

**3. 編集操作をコマンド化する**

UIからの編集とAIからの編集を共通化する。

**4. 音楽時間を共通化する**

コード、メロディ、伴奏を同じ音楽時間軸上で扱う。

**5. 未完成のデータを許容する**

メロディが存在しない、コード進行が途中で終わっている、といった状態を正常なスケッチとして扱う。

## 10. 開発ロードマップ

### Phase 1：コード進行を入力して鳴らす

最初のプロトタイプ。

**目標：iPadでコード進行を入力し、音を鳴らせること。**

実装範囲：

- SwiftUIによるコード進行エディタ
- コードの追加・変更・削除
- テンポ設定
- AVAudioUnitSamplerによるピアノ再生
- 簡単な伴奏パターン
- ローカル保存

最初の動作確認：

```text
Tempo: 120
Time: 4/4

| C | Am | F | G |
```

再生ボタンを押すと、4小節のコード進行がピアノで鳴る。

コードを変更して再生し直すことができる。

### Phase 2：音楽のメモ帳として成立させる

- 複数スケッチの作成・管理
- テキストメモ
- コード進行の複製・並べ替え
- Undo / Redo
- iPhone対応
- Mac対応
- iCloud同期

この段階で、**思いついたコード進行をiPhoneにメモし、iPadで続きを作る**という基本的な使い方を実現する。

### Phase 3：メロディと外部連携

- 五線譜の表示
- メロディの入力・編集
- メロディとコードの同時再生
- MIDI書き出し
- WAV書き出し
- Logic ProやSunoとの連携

### Phase 4：音楽的な編集機能

- モチーフの複製・変形
- フレーズの移調・反行・逆行
- コード進行のバリエーション管理
- コードとメロディの関係の可視化
- ボイスリーディングの調整

### Phase 5：AI連携

- AIによる楽曲構造の読み取り
- 自然言語から編集コマンドへの変換
- AIによる複数操作の実行
- 編集結果のプレビュー
- AIによる作曲支援

ただし、Phase 1から編集コマンドAPIを設計し、AI連携を後付けできるようにする。

## 13. 開発における優先順位

このプロジェクトでは、以下の優先順位を維持する。

**第1優先：思いついた音楽を素早く記録できること**

入力に手間がかかるようでは、メモ帳として成立しない。

**第2優先：すぐに音を確認できること**

コード進行を入力したら、簡単な伴奏ですぐに聴けること。

**第3優先：気軽に試行錯誤できること**

コードの変更、複製、並べ替え、Undoなどが軽快に行えること。

**第4優先：デバイスをまたいで利用できること**

iPhoneでメモし、iPadで作曲し、Macで仕上げにつなげる。

**第5優先：音楽的な構造を扱えること**

単なるMIDIイベントの編集ではなく、コードやフレーズの関係を編集できること。

**第6優先：AIと自然に連携できること**

人間とAIが同じ編集操作を利用できる構造を維持する。

## 15. プロジェクトの本質

このプロジェクトが目指すのは、作曲作業のすべてを置き換えることではない。

作曲中には、完成した曲になる前の、小さなアイデアが数多く生まれる。

コード進行だけを思いつくこともあれば、短いメロディや、既存のフレーズの変形を思いつくこともある。

そうしたアイデアを、紙のメモ帳に書くような気軽さで記録し、必要に応じて音を鳴らし、少しずつ発展させられる環境を作る。

そして、十分にアイデアが育ったら、Logic ProやSunoに渡して完成させる。

将来的には、AIも同じ編集環境に参加し、ユーザーの指示に従って音楽的な操作を実行できるようにする。

### コンセプトを一文で表すなら

**「思いついた音楽を、書き留め、聴き、育てるためのメモ帳。」**

### 補足：設計上、特に維持したい考え方

ここまでの議論で、技術的に特に重要だと考えるのは、次の3点です。

**① 楽曲モデルを中心に据えること。** 五線譜、コード表示、MIDI再生、AI編集は、すべて同じ楽曲モデルに対する異なるインターフェースとする。

**② 編集操作を共通化すること。** タッチ操作、マウス操作、キーボード操作、AIによる操作は、同じコマンドAPIを通じて楽曲を変更する。

**③ スケッチの自由度を失わないこと。** 一般的なDAWのように、すべてを完成した楽曲の時間軸に配置する必要はない。断片、別案、未完成のフレーズを自然に扱えることが、このアプリの価値になる。

この3点を維持できれば、最初はシンプルなコード進行エディタでも、将来的にかなり独自性のある作曲環境へ発展させられると思います。
